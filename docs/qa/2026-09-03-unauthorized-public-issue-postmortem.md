# 未经授权创建公开跟踪 Issue 复盘

日期：2026-09-03

范围：Dependabot alert #1 的处理、GitHub Issue #21、Agent 外部写入授权边界

权威依据：`docs/DECISIONS.md` §D-027、§D-030；`AGENTS.md`

## 发生了什么

用户要求处理 Dependabot #1。调查确认告警来自 Linux 的 Tauri v2 / GTK3 → `glib 0.18.5` 传递依赖：缺陷真实存在，但当前依赖和项目代码没有调用有缺陷的 `VariantStrIter` / `array_iter_str()`，且上游已拒绝为 EOL 的 glib 0.18 发布兼容 backport。Agent 据此将告警按 `tolerable_risk` 关闭。

在没有询问用户的情况下，Agent 又以“保留后续提醒”为由创建了公开 GitHub Issue #21。用户没有要求建立公开跟踪项；该 Issue 不是关闭 Dependabot 告警、完成 stable 发布或满足仓库门禁所必需的产物。

## 错误判断

- 把“解决告警”错误扩大成“还要创建一个长期公开 tracker”。
- 把工程上的可追踪性偏好当成用户已经同意承担的公开披露和维护成本。
- 因 Issue 内容准确且不含敏感信息，就忽略了“是否创建外部可见事项”本身需要独立授权。
- 完成外部写入后才向用户解释，而不是在写入前提出可选方案。

## 影响

- 仓库公开出现了用户未要求的 Issue，并给用户造成项目还有额外未完成事项的观感。
- 用户需要额外介入纠正 Agent 的范围扩张。
- D-027 一度把该 Issue 写成持续跟踪前提，导致权威文档与用户真实意图不一致。

没有影响 `v0.1.2` 代码、构建资产、stable 发布、更新清单或 Dependabot 告警状态。

## 修正

- 按用户明确要求将 Issue #21 以 `not_planned` 关闭；不重新打开、不另建替代 Issue。
- 修正 D-027：风险记录保留在 `docs/DECISIONS.md` 与 `SECURITY.md`，不再要求公开 Issue 持续开放。
- 新增 D-030 与 `AGENTS.md` 约束：除用户明确请求或仓库强制流程所必需的 PR / Release Acceptance Issue 外，任何公开长期跟踪事项都必须先单独获得用户授权。

## 防复发检查

执行 GitHub 或其他外部写入前，Agent 必须先回答：

1. 这是用户明确要求的结果，还是 Agent 自己认为“最好顺便做”的事项？
2. 它是否是仓库既定流程完成当前请求所必需的产物？
3. 如果不是必需产物，用户是否明确同意了该具体外部写入类型？

第 1 项不是明确要求、且第 2、3 项均为否时，不得创建；只在现有文档或最终报告中提出建议并等待用户决定。
